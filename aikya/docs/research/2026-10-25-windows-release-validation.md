## CI and release rehearsal

The Validation workflow checks Linux, macOS and Windows. Windows also performs real installs with both `pwsh` and `powershell.exe` in all three scopes, including spaces/Unicode paths. Tests use disposable Claude configurations.

The Release workflow rehearses on a push to `featuree/install-IDE`: resolve VERSION/changelog and commit SHA, reuse the full OS matrix, build eight assets, upload/download them as an immutable Actions artifact and verify the downloaded inventory and SHA256 sums. Branch rehearsals skip the publishing job.

Stable tag pushes publish after validation. Manual runs for existing tags default to dry-run; publication requires `dry_run=false`. The publishing job alone has write permission. It checks the tag still points at the validated SHA and publishes the verified assets through a draft using the changelog notes.

Remote results are recorded after the push. A local result is not a substitute for the Windows runner or artifact round trip.

## Limits

Publication is tested through a stateful GitHub CLI boundary; the branch rehearsal exercises real Actions packaging/artifacts without creating a GitHub release.
