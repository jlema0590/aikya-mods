# Aikya Usage

A native Claude Code mod that displays Context, Tokens and Usage together on one compact line below the terminal prompt. All interface text is in English.

## Install

From your terminal, install directly from the hosted marketplace:

```sh
claude plugin install aikya-usage --marketplace jlema0590/aikya-mods
```

This installs only `aikya-usage`. To install the other mods, run their matching commands in the [installation guide](../../README.md#install-a-specific-mod).

From the repository root:

```sh
bash mods/aikya-usage/install.sh
```

Or in Claude Code, from the public repository:

```text
/plugin install aikya-usage --marketplace jlema0590/aikya-mods
```

Restart Claude Code. The footer is enabled automatically; no usage card occupies the side pane. Flow and BoxBot remain independent.

## Readings

When `claude` runs in an IDE's integrated terminal, this line belongs to Claude's terminal prompt and continues to use Claude's own metrics. See the [integrated-terminal validation matrix](../../docs/terminal-compatibility.md) for configuration sharing and actual per-IDE validation status.

Example values:

```text
Context: 42% | Tokens: 53k | Usage 5h [====------] 40% | 7d [========--] 80%
```

- **Context** is the current context-window percentage reported by Claude Code.
- **Tokens** are observed input, output, cache-read and cache-write tokens since the mod loaded. They include subagent requests. The mod does not read earlier transcripts or claim a lifetime/session-history total after a reload.
- **Usage** is the account's five-hour and seven-day percent used, as reported by Claude Code. Missing or expired readings show `N/A`; they are never derived from token counts.

Each window has its own bar: `=` is used capacity and `-` is remaining capacity. Its percentage follows the bar. A ten-cell bar is approximate; the percentage retains the native reading rounded to at most one decimal. A value above 100% fills the bar without hiding the actual percentage.

Consumed cells and their percentage use the theme's `success` color below 70%, `warning` from 70% to below 90%, and `error` at 90% or higher. In a typical dark theme these are green, yellow and red. The windows are colored independently. Brackets and labels stay neutral, remaining cells are dim, and N/A uses question-mark cells with an inactive color. The thresholds are visual cues, not account limits or task progress.

Bars shorten from ten to five, two or one cell as space decreases, and labels are abbreviated in narrow terminals. A numeric fallback keeps the window labels and readings when bars cannot fit. The host can still clip the smallest format if the terminal is extremely narrow or other native footer content occupies the row. No additional row is added. Colors follow the user's theme and terminal color preferences; the mod does not force ANSI colors. The detailed command preserves the full meaning of each value. The permanent footer uses the native `PromptHint` site where the host exposes it; the terminal is the target surface. Other interfaces can consult `/aikya-usage` for the same data.

## Commands

```text
/aikya-usage
/aikya-usage hide
/aikya-usage show
```

The default command reports the current context, token categories, coverage and native estimated USD cost without opening a pane or calling a model. Missing counts and prices show N/A; zero is used only for an actual zero reading.

The token ledger deduplicates request identities by agent, turn and step. A final turn total replaces the observed step subtotal, so it is not added twice. The ledger resets after clear/resume/session end and reload. It retains up to 256 turns and 256 steps per turn; hitting a bound marks coverage partial and does not evict old identities to recount them.

The mod reads the inexpensive native usage snapshot and observes existing streams. It does not request full context token counts, inspect credentials, write files, change permissions or make model/network requests. Cost is Claude Code's estimate, not an invoice.
