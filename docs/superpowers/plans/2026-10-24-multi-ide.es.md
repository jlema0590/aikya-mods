# Aikya Mods para Cursor, Trae y JetBrains — Implementation Plan

> **Sustituido el 2026-10-25:** el usuario aclaró que los mods deben ejecutarse en Claude Code dentro de las terminales integradas. Este plan de extensiones nativas queda archivado y no debe ejecutarse. Plan activo: [Claude en terminales integradas](2026-10-25-claude-integrated-terminals.es.md).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** añadir paquetes instalables de los tres mods en Cursor, Trae y productos IntelliJ Platform, conservando la instalación de Claude y documentando las capacidades reales de cada proveedor.

**Architecture:** una extensión VSIX reutiliza las funciones JavaScript actuales mediante un adaptador neutral. Un plugin Kotlin/Swing implementa la misma semántica mediante contratos y casos JSON compartidos. Los hooks observadores y el lector del caché Aikya son fuentes separadas; ninguna interfaz presume acceso universal a la telemetría de los agentes.

**Tech Stack:** JavaScript ES modules, TypeScript, VS Code Extension API estable, HTML/SVG, Node 22+, Kotlin/Swing, JDK 21, Gradle IntelliJ Platform Plugin 2.x, Python unittest y kit de pruebas de Claude.

**Spec:** [análisis de impacto y requisitos](../../../aikya/docs/research/2026-10-24-multi-ide-impact.es.md). Leer especialmente los requisitos 1–14 y el límite de paridad de telemetría.

## Global Constraints

- Interfaz y mensajes de producto en inglés. Los tres plugins actuales de Claude conservan instalación independiente.
- Un VSIX para Cursor/Trae y un ZIP para JetBrains; módulos activables por separado. Distribución inicial desde disco.
- Sin modificar el núcleo Aikya ni el schema 1 existente. La identidad sigue siendo SHA256 de raíz canónica, NUL y sesión del productor.
- No importar rutas externas al paquete instalado. No usar APIs privadas del agente ni leer credenciales/transcripciones para completar métricas.
- Datos ausentes: `N/A`; fases sin evidencia: `No evidence`. No derivar cuotas de tokens ni completar fases por éxito de herramientas.
- Ledger: 256 turnos y 256 pasos por turno. No fabricar categorías de tokens o identificadores ausentes.
- BoxBot: 125 ms entre cuadros, 64 cuadros por bucle, sin controles dentro de la escena.
- Lectores: máximo una consulta cada 2.000 ms por conexión visible; evento máximo 64 KiB y snapshot máximo 2.000.000 bytes.
- Node 22+ para herramientas y observadores; JDK 21/baseline JetBrains 2025.3, comprobación adicional en 2026.2/Java 25.
- Bash 3.2/macOS/Linux. `--target claude` por defecto. Otros destinos solo admiten `--scope user` inicialmente.
- Pruebas de instalación con perfiles temporales; no instalar en la configuración habitual del usuario ni publicar en marketplaces en este plan.

## Review Focus

- Proyecto multi-root y dos sesiones simultáneas: selección explícita y ninguna mezcla de identidad; tareas 2, 3 y 5.
- Evento duplicado, sin ID estable o fuera de orden: cobertura parcial y ningún doble conteo ni finalización inventada; tareas 2 y 3.
- Lectura pendiente al desconectar/cambiar sesión: no restaura datos anteriores; tareas 2 y 5.
- Métrica de otro proveedor o contexto puntual antiguo: etiqueta y fecha correctas, sin ventanas 5h/7d ajenas; tareas 2, 4 y 5.
- Rutas con espacios, permisos de escritura insuficientes o paquete incompatible: fallo antes de cambios parciales y sin tocar configuración ajena; tareas 3 y 6.

### Tarea 2: contratos y runtime JavaScript independientes de Claude

**Archivos:** crear esquemas y fixtures de `contracts/`, los cuatro módulos de `integrations/shared/`, `integrations/shared/package.json` y `integrations/shared/tests/{contracts,runtime,snapshot-reader,usage-view}.test.js`.

**Interfaces:** `decodeEvent(raw: unknown): ModEvent | null`; `createRuntime(): Runtime`; `applyEvent(runtime, event): void`; `readView(runtime, selection): ModView`; `readSnapshot(io, selection, previous): Promise<Snapshot | null>`; `formatUsage(view): {text: string, detail: string}`. `io` ofrece `realpath`, `stat` y `readText`; no contiene APIs del editor.

`ModEvent` tiene `schema: 1`, `eventId`, `provider`, `projectRoot`, `sessionId`, `observedAt` en milisegundos, `kind` y `payload`. `provider` es `cursor|trae|claude`; `kind` es `session.start|session.end|turn.start|turn.end|tool.start|tool.end|usage`. `turnId`, `agentId`, `stepIndex` y `toolCallId` son opcionales y se conservan solo si la fuente los suministra. No se fabrica su valor. Un evento sin correlación suficiente actualiza únicamente actividad observada; no cierra un turno ni alimenta el ledger.

`Selection` es `{provider, projectRoot, sessionId, cacheRoot: string|null}`. `UsageView` distingue contexto `{percent,tokens,window,observedAt}|null`, tokens observados por categorías explícitas o total independiente, `quotaWindows: [{id,label,percentUsed,resetsAt}]`, `costUsd|null` y `coverage: observed|partial|unavailable`. `ModView` contiene esa lectura, Flow, proveedor y fecha; snapshots son datos del schema 1, no otro schema de ejecución.
